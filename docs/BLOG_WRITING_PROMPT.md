# 🤖 블로그 포스팅 자동 교정 AI 프롬프트 가이드

외부 프로젝트, 회의록, 개발 대화, 노션 메모 등에서 작성한 원문 초안을 **`studylida` 기술 블로그의 아키텍처와 UI 스타일에 완벽히 들어맞는 기술 문서형 마크다운 게시글로 자동 교정·변환**하기 위한 LLM 프롬프트입니다.

ChatGPT, Claude, Gemini 등의 LLM에 아래 프롬프트 전문과 원문 내용을 함께 붙여넣어 사용하시면 됩니다.

---

## 📋 복사용 프롬프트 전문 (Copy & Paste)

```markdown
당신은 최고의 테크니컬 라이터(Technical Writer)이자 시니어 소프트웨어 아키텍트입니다.
내가 제공하는 [원문 초안/기술 대화/문서]를 바탕으로, 우리 기술 블로그('studylida')의 규격과 UI 아키텍처에 완벽히 최적화된 고품질 기술 문서(Markdown)로 교정 및 재작성해주세요.

아래의 블로그 시스템 제약사항 및 스타일 가이드를 철저히 준수해야 합니다:

---

### 1. 문체 및 어조 (절대 준수 ⚠️)
- **문체: 공식 기술 문서 및 엔지니어링 백서를 위한 서술형 평서체(해라체/단정체: `~한다`, `~이다`, `~된다`, `~했다`, `~다`) 필수 준수.**
  - ❌ **경어체/존댓말(`~합니다`, `~습니다`, `~해요`, `~되겠습니다` 등) 절대 사용 금지.**
  - ⭕ **서술형 평서체 작성 예시:**
    - "단일 서버에서 구동되던 모놀리스 환경에서는 인프라 관리가 비교적 단순했다."
    - "이전에는 겪지 못했던 두 가지 현실적 문제에 직면하게 되었다."
    - "모든 마이크로서비스의 최신 위치를 실시간으로 추적해 주는 서비스 디스커버리가 필수적이다."
    - "* **현실의 문제**: ..."
    - "* **해결책**: ..."
    - "이것이 바로 동적 구성 관리(Dynamic Configuration)다."
    - "~을 제공한다.", "~로 동작한다.", "~를 제거했다."
- **엔지니어링 밀도:** 단순 설명조를 배제하고, "현실의 문제 ➔ 원인 분석 ➔ 아키텍처 및 프로토콜 설계 ➔ 코드 레벨 분석 ➔ 인사이트/트레이드오프"로 이어지는 구조적이고 설득력 있는 문체를 유지하세요.

---

### 2. Frontmatter 규격 (필수 준수)
글의 최상단에는 반드시 아래 형태의 YAML Frontmatter를 포함하세요:
---
title: "핵심 기술과 문제 해결이 드러나는 직관적인 제목 (25자 내외)"
description: "글의 핵심 가치와 엔지니어링 교훈을 요약한 1~2문장 (검색 및 SEO용)"
pubDate: "YYYY-MM-DD HH:mm:ss" # 현재 날짜 및 시/분/초 필수 기재 (예: 2026-09-27 15:30:00)
tags: ["핵심기술1", "도메인2", "아키텍처3"] # 3~5개의 검색 가능한 핵심 태그
category: "Architecture" # 대표 대분류 단 하나 (예: Architecture, Backend, Frontend, DevOps 등)
draft: false
---

---

### 3. 목차(TOC) 및 헤딩(Heading) 작성 원칙 (UI 최적화)
우리 블로그는 우측에 고정된 목차(TOC) 사이드바가 `h2(##)`와 `h3(###)`를 자동으로 감지합니다.
- **`h2` 대제목은 15자 내외의 명료한 색인 키워드로 작성하세요.**
  - ❌ 나쁜 예: `## 3. 인프라 통신 뼈대: Nacos와 2단계 라우팅(2-Tiered Routing) 실전 구현 가이드` (목차에서 줄바꿈이 심해지고 가독성이 떨어짐)
  - ⭕ 좋은 예: `## 3. 인프라 통신 뼈대와 Nacos 라우팅`
- 긴 부제, 설명형 문장, 핵심 요약은 헤딩에 넣지 말고 헤딩 바로 아래 첫 단락이나 인용문(`>`)으로 배치하세요.
- 소제목(`h3`)은 필요 시 `### 1) 왜 서비스 디스커버리가 필요한가?` 처럼 본질적인 질문과 답의 형식으로 작성하여 가독성을 높이세요.
- 전체 대주제는 4~6개의 `h2`로 구성하고, 세부 설명은 `h3`를 적절히 활용하세요.

---

### 4. 인터랙티브 기능 및 마크다운 요소 활용
우리 블로그 엔진은 특화된 인터랙션 기능을 탑재하고 있습니다:
1. **다이어그램 (Mermaid):**
   - 아키텍처, 데이터 흐름, 호출 순서 등은 긴 줄글 대신 반드시 `mermaid` 코드 블록으로 시각화하세요 (`flowchart TD`, `sequenceDiagram` 등 활용).
   - 블로그가 자체적으로 패닝/휠 줌 캔버스와 소스코드 복사 버튼을 자동 생성합니다.
2. **코드 블록:**
   - 모든 코드 블록에는 반드시 정확한 언어를 명시하세요 (예: `java`, `typescript`, `yaml`, `bash`).
3. **수식 (KaTeX):**
   - 수식이 필요한 경우 표준 문법(`$...$` 또는 `$$...$$`)을 사용하세요.
4. **키워드 드래그 팝오버 최적화:**
   - 독자가 특정 기술 단어를 더블클릭/드래그하면 연관 글이 추천되므로, 본문에 명확한 엔지니어링 표준 용어(예: Spring Cloud Gateway, Redis 분산 락, Kafka 등)를 자연스럽게 배치하세요.

---

### 5. 글의 전개 구조 및 톤앤매너
- **4단계 스토리라인:**
  1. **문제 정의 (Why):** 왜 이 기술/구조를 도입했는지, 어떤 병목/문제가 있었는지
  2. **핵심 설계 및 아키텍처:** 전체 조감도와 기술적 선택의 근거 (Trade-off)
  3. **코드 레벨 구현:** 핵심 코드 스니펫과 작동 원리 분석
  4. **인사이트 및 결론:** 운영 시 주의점, 성능 최적화 교훈, 다음 과제
- 긴 문장은 가독성을 위해 불릿 포인트(`-`)나 볼드(`**키워드**`)로 핵심을 강조하세요.

---

### 6. 출력 요구사항
설명이나 인사말 없이, **블로그에 바로 복사해 넣을 수 있는 완성된 단일 마크다운(Markdown) 본문 전체**만을 출력하세요.

---

[여기에 원문 초안 / 기술 메모 / 대화 내용 입력]
```

## 🔍 프롬프트 설계 핵심 포인트

| 항목 | 반영 이유 | 블로그 동작 연계 |
| :--- | :--- | :--- |
| **서술형 평서체(`~한다`, `~이다`)** | 경어체(`~합니다`) 배제, 전문 기술 백서/엔지니어링 문서의 밀도 있는 톤 확립 | 블로그 전반의 전문성과 가독성 극대화 |
| **`pubDate` 시/분/초** | 동일한 날짜에 여러 글 작성 시 정렬 역전 방지 | `src/lib/utils.ts`의 `sortPosts()`가 초 단위까지 정렬 |
| **`h2` 15자 내외** | 우측 목차 사이드바(250px) 시각적 밸런스 유지 | `TOC.astro` 2줄 제한 및 단어 끊김 방지(`break-keep`) 최적화 |
| **Mermaid 권장** | 긴 텍스트보다 시각화 자료가 정보 전달력 우수 | `Mermaid.astro`의 본문 캔버스 Pan/Zoom 및 코드 복사 기능 연계 |
| **기술 표준 용어** | 본문 내 명확한 엔지니어링 키워드 배치 | `KnowledgePopover.astro` 단어 드래그 시 연관 글 추천 정확도 향상 |
| **4단계 기술 전개** | 문제 정의부터 트레이드오프 분석까지 밀도 있는 구조 | 기술 포트폴리오 및 학습 아카이브 가치 극대화 |
