## 1. 전체 학습 순서와 완료 기준

**지금 듣는 RAG 강의를 마친 뒤 머신러닝 1·2과목을 듣고, 결정 트리를 배운 시점에 첫 XAI 실습을 진행한다.** 그다음 머신러닝 3과목을 마치고 딥러닝으로 넘어간다. 두 번째 XAI 실습은 CNN을 배운 직후에 진행한다. 이렇게 구성하면 강의에서 배운 모델을 기억하고 있을 때 직접 분석해 볼 수 있다.

| 순서 | 공부할 내용 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| 1 | 현재 RAG 강의 마무리 | 답변 하나가 틀렸을 때 검색, 문맥 구성, 생성 중 어디서 문제가 생겼는지 구분할 수 있다. |
| 2 | 머신러닝 특화 과정 1·2과목 | 간단한 기준 모델을 세우고, 데이터를 나눠 모델 성능과 오차를 비교할 수 있다. |
| 3 | KAIST XAI 입문 + 표 데이터 실습 | 모델 전체의 변수 중요도와 개별 예측의 설명을 구분하고, 설명을 추가 실험으로 점검할 수 있다. |
| 4 | 머신러닝 3과목 + 딥러닝 1\~4과목 | 신경망이 어떻게 학습되는지 설명하고, 학습 곡선과 오답을 보고 다음 실험을 정할 수 있다. |
| 5 | KAIST CNN 해석 + 이미지 실습 | Grad-CAM이 강조한 영역을 바꿔 보고, 분류 점수가 실제로 어떻게 달라지는지 확인할 수 있다. |
| 6 | 딥러닝 5과목 + RAG 마무리 실험 | 트랜스포머의 어텐션을 이해하고, 근거가 바뀔 때 LLM 답변이 어떻게 바뀌는지 비교할 수 있다. |

주 8\~10시간을 투자한다면 **현재 RAG 강의의 남은 분량 이후 약 7\~8개월**이 소요된다. 두 특화 과정의 과목별 안내 시간에 실습 시간을 더한 추정치다.
- 참고 과정: [Coursera 머신러닝 과정](https://www.coursera.org/specializations/machine-learning-introduction), [Coursera 딥러닝 과정](https://www.coursera.org/specializations/deep-learning)

## 2. RAG 강의 모듈별 실습

Zain Hasan의 강의는 5개 모듈로 구성되어 있다. 이미 끝낸 모듈은 과제나 노트에서 아래 내용을 확인하고, 남은 모듈은 이 기준으로 공부한다. 특히 **2번 검색 평가, 3번 청킹·재정렬, 5번 평가·추적**에 시간을 더 할애한다.
- 강의 링크: [현재 듣는 Coursera RAG 강의](https://www.coursera.org/learn/retrieval-augmented-generation-rag)

| 모듈 | 강의를 들으면서 직접 해볼 것 |
|---|---|
| **1. RAG Overview** | 과제에서 질문 하나를 실행하고, 검색 결과와 LLM에 실제로 전달한 문맥을 따로 출력한다. |
| **2. Search Foundations** | 같은 질문으로 BM25, 벡터 검색, 하이브리드 검색을 비교한다. 정답 근거가 상위 5개에 들어오는지와 몇 위인지 기록한다. |
| **3. Vector Databases** | 청킹 또는 재정렬 중 하나를 바꾼다. 정답 구간이 색인에 있는지, 검색 후보에 들어왔는지, 재정렬 후 문맥에 남았는지 차례로 확인한다. |
| **4. LLMs and Text Generation** | 같은 질문을 검색 결과를 넣은 경우와 정답 근거를 직접 넣은 경우에 각각 실행한다. 정답 근거를 줘도 답이 틀린다면 생성 단계에서 따로 볼 문제다. |
| **5. RAG Systems in Production** | `Tracing a RAG system` 실습을 하면서 질문, 검색 후보, 전달 문맥, 최종 답변이 어떻게 이어지는지 확인한다. |

마무리로 **강의 자료에서 답을 찾을 수 있는 질문 8개와 답을 찾을 수 없는 질문 2개**를 만든다. 문서명이나 정확한 용어가 있는 질문, 표현을 바꿔 물은 질문, 여러 구간을 함께 읽어야 하는 질문을 섞는다. 답변을 생성하기 전에 필요한 원문 위치를 표시해 두고, 실패할 때는 **후보에 없었음 / 후보에는 있었지만 문맥에서 빠졌음 / 문맥에 있었지만 답이 틀렸음** 중 어디인지 적는다. 이 질문 세트는 마지막 단계에서 그대로 다시 사용한다.

## 3. 머신러닝 1·2과목 핵심

- **1과목 · 회귀와 분류**: 선형 회귀에서 예측값, 손실, 경사하강법이 어떻게 연결되는지 익힌다. 작은 데이터로 가중치를 한 번 갱신하는 코드를 직접 적어 보면 충분하다. 로지스틱 회귀에서는 확률을 분류 결과로 바꾸는 기준값을 조정하고, 어떤 오답이 늘거나 줄어드는지 확인한다. ([Coursera 1과목](https://www.coursera.org/learn/supervised-machine-learning-regression-and-classification))
- **2과목 · 신경망, 모델 평가, 결정 트리**: 모델 평가 파트에서 학습용, 검증용, 테스트용 데이터의 역할을 정리한다. 결정 트리 파트에서는 같은 데이터로 얕은 트리와 깊은 트리를 학습시키고, 학습 오차와 검증 오차가 어떻게 달라지는지 비교한다. 랜덤 포레스트까지 실습해 보면 첫 XAI 실습으로 넘어갈 준비가 완료된다. ([Coursera 2과목](https://www.coursera.org/learn/advanced-learning-algorithms))

## 4. 자전거 대여량 XAI 실습

**이 단계에서 XAI를 직접 구현해 본다.** KAIST 2023년 튜토리얼의 **3번 전역 설명 ➔ 4번 개별 예측 설명 ➔ 10번 설명 평가** 순서로 학습한다. 3번을 본 뒤 변수 중요도를 계산하고, 4번을 본 뒤 하루치 예측을 설명하는 식으로 영상과 코드를 번갈아 진행한다.
- 튜토리얼 자료: [KAIST XAI 튜토리얼 녹화·자료](https://xai.kaist.ac.kr/Tutorial/2023/)

1. **예측 문제를 정한다**: UCI 데이터의 `day.csv`에서 날짜와 날씨가 주어졌을 때 하루 전체 대여량 `cnt`를 추정한다. 날짜순으로 학습, 검증, 테스트 구간을 나누고, 학습 구간의 요일별 평균을 기준 모델로 둔다. 얕은 결정 트리와 랜덤 포레스트를 같은 구간에서 비교한다. 지표는 평균 절대 오차(MAE) 하나면 충분하다. ([UCI Bike Sharing 데이터](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset))
2. **모델이 평소 무엇에 의존하는지 본다**: 검증 데이터에서 온도 열의 값 순서만 섞고, 이미 학습한 모델로 다시 예측한다. 오차가 얼마나 늘었는지 계산하고, 다른 변수에도 반복한다. 이 과정을 먼저 직접 구현한 뒤 scikit-learn의 순열 중요도와 비교한다. ([scikit-learn 순열 중요도](https://scikit-learn.org/stable/modules/permutation_importance.html))
3. **크게 틀린 하루를 골라 설명한다**: 실제값, 예측값, 오차를 먼저 적는다. `TreeExplainer`와 SHAP 워터폴 그래프로 어떤 입력이 그날의 예측을 기준값에서 위아래로 움직였는지 확인한다. 비슷한 조건에서 잘 맞힌 날 하나도 골라 설명을 비교하면, 모델이 어떤 상황에서 흔들렸는지 가설을 세울 수 있다. ([SHAP TreeExplainer](https://shap.readthedocs.io/en/stable/generated/shap.TreeExplainer.html), [워터폴 그래프 예제](https://shap.readthedocs.io/en/stable/example_notebooks/api_examples/plots/waterfall.html))
4. **설명이 실제 진단에 도움이 되는지 확인한다**: 당일 회원·비회원 대여 건수인 `registered`와 `casual`을 일부러 입력에 넣고 같은 조건에서 다시 학습해 본다. 두 값을 합치면 예측 대상인 `cnt`가 된다. 점수와 변수 중요도가 어떻게 달라지는지 비교하고, **예측하는 시점에 알 수 없는 정보가 들어가면 왜 평가가 왜곡되는지** 설명해 본다. ([UCI 변수 정의](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset))

완료 기준은 그래프 개수가 아니라, **"모델이 무엇에 의존했다는 가설을 세웠고, 어떤 실험으로 어디까지 확인했다"**를 설명할 수 있는지 여부다. 예를 들어 SHAP에서 온도의 기여도가 크게 나왔으면, 그 결과로 설명할 수 있는 범위는 해당 모델의 예측이다. 실제 대여량에 대한 온도의 인과 효과는 별도의 질문이다. ([SHAP 해석 범위와 가정](https://shap.readthedocs.io/en/stable/generated/shap.TreeExplainer.html))

## 5. 머신러닝 3과목과 딥러닝

머신러닝 **3과목**은 군집화, 이상 탐지, 추천 시스템, 강화학습의 강의와 과제를 따라간다. 군집을 묶는 일, 비슷한 항목을 추천하는 일, 행동에 대한 보상을 학습하는 일이 각각 어떤 문제인지 설명할 수 있으면 충분하다. ([Coursera 머신러닝 3과목](https://www.coursera.org/learn/unsupervised-learning-recommenders-reinforcement-learning))

딥러닝은 과목마다 아래 **한 가지 실습**에 집중한다. ([Coursera Deep Learning Specialization](https://www.coursera.org/specializations/deep-learning))

| 과목 | 실습 |
|---|---|
| **1. 신경망 기초** | 작은 신경망에서 입력 ➔ 예측 ➔ 손실 ➔ 기울기 ➔ 가중치 갱신을 손으로 따라가고, 코드의 각 줄이 어느 단계인지 설명한다. |
| **2. 최적화와 정규화** | 학습률만 바꾼 실험과 정규화만 바꾼 실험을 따로 수행한다. 학습·검증 곡선을 보고 학습이 불안정한 경우와 과적합을 구분한다. |
| **3. 머신러닝 프로젝트 구성** | 오답을 10\~20개 골라 유형별로 분류한다. 가장 흔하거나 영향이 큰 문제를 고르고, 데이터, 모델, 평가 중 어디를 먼저 바꿀지 정한다. |
| **4. CNN** | 합성곱을 거치면서 이미지 크기와 채널 수가 어떻게 바뀌는지 출력해 본다. 분류 직전의 특성 지도를 찾으면 Grad-CAM 실습으로 넘어간다. |

## 6. 이미지 분류 XAI 실습

KAIST의 **5번 CAM-based methods**와 **11번 PyTorch 실습**을 학습한다. 이미 학습된 ResNet 하나와 이미지 5\~10장이면 시작할 수 있으며, 맞힌 사진과 틀린 사진을 함께 고른다.
- 참고 자료: [KAIST CNN·PyTorch 실습](https://xai.kaist.ac.kr/Tutorial/2023/), [Captum LayerGradCam](https://captum.ai/api/layer.html#gradcam)

1. 원본 이미지의 예측 클래스와 점수를 기록하고 Grad-CAM으로 강조 영역을 표시한다.
2. 강조 영역을 가린 이미지와 같은 크기의 다른 영역을 가린 이미지를 각각 넣는다. **비교할 클래스는 원본에서 정한 것으로 고정**하고, 그 클래스의 점수가 얼마나 떨어지는지 확인한다.
3. 기대와 다른 이미지도 남긴다. 가리는 방식 자체가 입력을 크게 바꿀 수 있으므로, 결론이 애매한 사례는 검은색으로 가리는 대신 흐리게 처리해도 결과가 비슷한지 확인한다. ([Captum 이미지 가림 실습](https://captum.ai/tutorials/TorchVision_Interpret))

## 7. 트랜스포머와 RAG 실험

딥러닝 **5과목 Sequence Models**에서 RNN·LSTM, 어텐션, 트랜스포머를 공부한다. 트랜스포머 파트에서는 짧은 문장 하나를 두고 **쿼리와 키로 가중치를 구한 뒤, 그 가중치로 값을 섞는 과정**을 직접 따라가 본다. ([Coursera Sequence Models](https://www.coursera.org/learn/nlp-sequence-models))

그다음 1단계의 질문 중 3\~5개를 골라 **검색 결과 그대로 / 정답 근거를 직접 제공 / 정답 근거만 제거**한 경우를 비교한다. 질문, 모델, 생성 설정은 고정하고, 답의 정확성과 근거에 없는 주장이 생기는지를 따로 기록한다. 나중에 로컬 LLM 튜닝을 다시 진행할 때도 같은 평가를 쓸 수 있다. 근거를 잘 주었을 때 이미 답을 잘한다면 검색이나 문맥 구성을 먼저 살펴볼 이유가 생기고, 근거를 충분히 주어도 같은 유형의 오류가 반복된다면 그때 모델 쪽 실험을 설계할 수 있다.

> [!IMPORTANT]
> **즉시 시작할 첫 번째 과제**
> 당장 실행할 일은 지금 듣는 RAG 과제에 `질문 / 필요한 원문 / 검색 순위 / 전달 여부 / 답변 결과` 다섯 칸을 붙여서 한 사례부터 채우는 것이다. KAIST 2023년 자료의 강의 순서와 코드 링크는 확인되었으며, 당시 코드의 최신 PyTorch 호환성은 실행 시점에 점검한다. 환경 설정에서 막히면 위의 Captum 공식 예제로 같은 이미지 실험을 진행하면 된다.
