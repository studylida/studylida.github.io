현재 RAG 서비스를 개발하면서 검색과 답변 품질을 개선하고 있다. 이 과정에서 모델을 사용하는 방법뿐 아니라, 왜 특정한 결과가 나오는지 분석하고 제한된 장비에서도 활용할 수 있도록 모델을 압축하는 방법까지 공부할 필요를 느꼈다.

이에 따라 기존에 나누어 작성했던 학습 계획을 하나로 정리한다. 현재 수강 중인 RAG 강의를 출발점으로 머신러닝과 딥러닝의 기초를 익히고, XAI 실습으로 모델의 행동을 분석하는 경험을 쌓는다. 이후 양자화와 지식 증류를 공부한 뒤, **E-Means를 코드북 양자화에 적용하고 압축 효과와 답변 품질을 비교하는 포트폴리오**로 연결한다.

강의를 많이 수료하는 것보다 중요한 목표는 다음 세 가지다.

- 문제가 발생했을 때 검색, 입력, 모델 중 어디에서 원인을 찾아야 하는지 판단한다.
- 모델과 데이터를 바꾸었을 때 무엇이 좋아졌고 무엇이 나빠졌는지 비교한다.
- 압축한 모델의 파일 크기뿐 아니라 실제 메모리, 속도, 업무 답변 품질까지 설명한다.

기본 실습 장비는 **RTX 3050 4GB 노트북**이다. 작은 모델과 데이터로 원리를 확인하고, 전체 언어 모델을 대상으로 큰 메모리가 필요한 실험은 별도 GPU 환경에서 진행한다.

## 1. RAG와 실패 지점 구분

### 강의

현재 수강 중인 [DeepLearning.AI의 Retrieval Augmented Generation 강의](https://www.coursera.org/learn/retrieval-augmented-generation-rag)를 마무리한다. 검색, 벡터 데이터베이스, 생성, 운영을 하나의 시스템으로 연결해 이해하는 단계다.

### 실습

작은 문서 묶음으로 RAG를 구성하고, 질문이 들어온 뒤 다음 정보가 어떻게 바뀌는지 기록한다.

**사용자 질문 → 검색 질의 → 검색 후보 → 재정렬 결과 → 최종 근거 → 답변과 인용**

처음부터 평가 질문도 함께 준비한다. 문서 이름을 직접 말하는 질문, 같은 내용을 다른 표현으로 묻는 질문, 여러 구간을 함께 읽어야 하는 질문, 자료만으로 답할 수 없는 질문을 포함한다.

각 질문에는 모델 답변을 보기 전에 필요한 원문 위치와 확인해야 할 사실을 표시한다. 이후 개선에 사용한 질문과 마지막 평가에 사용할 새 질문은 구분한다.

실패는 우선 다음과 같이 나눈다.

| 실패 유형 | 확인할 내용 |
|---|---|
| 필요한 근거가 검색 후보에 없음 | 질의 표현, 청킹, 키워드·벡터 검색 |
| 후보에는 있지만 최종 입력에서 빠짐 | 재정렬, 중복 처리, 문맥 선택 |
| 근거를 전달했지만 답변이 틀림 | 입력 형식, 프롬프트, 모델의 근거 활용 |

검색 방식이나 청킹을 바꿀 때는 한 번에 한 요소만 변경한다. 후보 수나 문맥 한도를 늘렸다면 그것도 별도의 변경으로 기록한다.

### 완료 기준

- 하나의 잘못된 답변을 보고 어느 단계부터 조사해야 하는지 설명할 수 있다.
- 검색된 자료와 모델이 실제로 읽은 자료를 구분할 수 있다.
- 변경 전후의 필요한 근거 순위, 최종 선택, 답변을 함께 비교할 수 있다.
- 근거가 없는 질문에서 모델이 사실을 만들어내는지도 확인한다.

**장비:** 작은 문서 묶음과 API 모델을 사용하는 실습은 현재 노트북으로 진행한다. 이 단계에서 큰 GPU를 마련할 필요는 없다.

## 2. 지도학습과 모델 평가

### 강의

[Machine Learning Specialization](https://www.coursera.org/specializations/machine-learning-introduction)의 첫 두 과정을 수강한다.

- Supervised Machine Learning: Regression and Classification
- Advanced Learning Algorithms

회귀, 분류, 신경망, 트리 모델을 배우면서 손실함수, 최적화, 과적합, 데이터 분할을 중심으로 정리한다.

### 실습

선형회귀와 로지스틱 회귀를 작은 데이터에서 직접 구현한다. 라이브러리를 호출하기 전에 예측값, 손실, 기울기, 가중치 갱신이 어떻게 연결되는지 확인한다.

이후 같은 데이터에 단순한 기준 모델, 얕은 결정트리, 랜덤 포레스트를 적용한다. 성능이 높은 모델만 고르지 않고, 어떤 데이터에서 어떤 오류가 줄었는지 살펴본다.

함께 보완할 수학은 다음 범위로 제한한다.

- 벡터·행렬과 행렬곱
- 미분과 연쇄법칙
- 평균, 분산, 확률분포
- 로그, 교차엔트로피와 최대우도
- 정규화와 일반화

수학을 모두 끝낸 뒤 실습하는 방식보다, 구현 중 설명이 막히는 부분을 돌아가며 공부한다.

### 완료 기준

- 학습 손실과 검증 성능이 다르게 움직이는 이유를 설명할 수 있다.
- 학습, 검증, 평가 데이터를 나누는 이유를 설명할 수 있다.
- 분류 임계값을 바꾸면 어떤 오류가 늘고 줄어드는지 확인한다.
- 복잡한 모델이 단순한 모델보다 항상 좋은 것은 아니라는 점을 실험으로 보여준다.

**장비:** 대부분 CPU로 충분하다. GPU보다 데이터 분할과 비교 조건을 정확히 설정하는 데 집중한다.

## 3. 표 데이터 XAI 실습

XAI는 모델이 왜 그런 예측을 했는지 조사하는 도구로 공부한다. 시각화를 만드는 데서 끝내지 않고, 설명을 바탕으로 가설을 세운 뒤 실제 변화와 비교한다.

### 강의·자료

[KAIST XAI 튜토리얼](https://xai.kaist.ac.kr/Tutorial/2023/)에서 다음 내용을 먼저 공부한다.

- 전체적인 모델 행동을 설명하는 방법
- 개별 예측을 설명하는 방법
- 설명의 품질을 평가하는 방법

실습 도구로는 [Permutation Importance](https://scikit-learn.org/stable/modules/permutation_importance.html)와 [SHAP TreeExplainer](https://shap.readthedocs.io/en/stable/generated/shap.TreeExplainer.html)를 사용한다.

### 실습

[UCI Bike Sharing 데이터](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset)의 일별 대여량을 예측한다.

날짜 순서대로 학습, 검증, 평가 데이터를 나누고, 단순한 기준 모델과 트리 모델을 비교한다. 잘 예측한 날과 크게 틀린 날을 골라 어떤 변수가 예측에 영향을 주었는지 조사한다.

이후 일부러 데이터 누수를 만들어본다. 전체 대여량을 예측하면서 그 합계를 구성하는 회원·비회원 대여량을 입력에 넣고, 성능과 변수 중요도가 어떻게 달라지는지 확인한다.

이 실습의 핵심은 **좋은 점수와 그럴듯한 설명이 있어도 잘못된 모델일 수 있다**는 사실을 직접 확인하는 것이다.

### 완료 기준

- 전체 변수 중요도와 특정 예측의 설명을 구분한다.
- 예측 시점에 알 수 없는 변수가 입력에 포함되었는지 점검한다.
- 설명을 바탕으로 입력이나 학습 조건을 바꿔 결과를 비교한다.
- 변수 중요도를 현실의 인과관계로 해석하지 않는다.

**장비:** CPU로 충분하다. SHAP 실습이 느리면 설명할 표본과 배경 데이터를 줄인다.

## 4. 군집화와 PyTorch 기초

### 강의

Machine Learning Specialization의 마지막 과정인 **Unsupervised Learning, Recommenders, Reinforcement Learning**을 수강한다. 이후 [Deep Learning Specialization](https://www.coursera.org/specializations/deep-learning)의 앞 세 과정을 공부한다.

- Neural Networks and Deep Learning
- Improving Deep Neural Networks
- Structuring Machine Learning Projects

비지도학습에서는 나중에 E-Means로 이어질 **k-means의 목적함수와 중심점 갱신 과정**을 특히 꼼꼼히 다룬다.

### 실습

먼저 작은 2차원 데이터에서 k-means를 구현한다. 초기 중심점과 군집 수를 바꾸며 결과를 비교하고, 학습 과정에서 거리 오차가 어떻게 감소하는지 그린다.

딥러닝에서는 작은 MLP를 학습한다. 학습률과 정규화는 따로 바꾸고, 학습·검증 곡선을 비교한다.

이후 같은 모델을 PyTorch로 다시 구현한다. 다음 동작을 직접 작성할 수 있도록 연습한다.

- 데이터를 배치로 읽는다.
- 순전파와 손실을 계산한다.
- 역전파와 가중치 갱신을 실행한다.
- 학습 모드와 평가 모드를 구분한다.
- 모델을 저장하고 다시 불러온다.
- 중간 텐서의 모양과 메모리 사용량을 확인한다.

### 완료 기준

- k-means가 최소화하려는 값과 중심점 갱신을 설명할 수 있다.
- 학습 루프를 예제 코드 없이 다시 작성할 수 있다.
- 기울기가 필요한 텐서와 필요하지 않은 텐서를 구분한다.
- 오류를 유형별로 모으고 다음 실험에서 바꿀 요소를 선택한다.

**장비:** 작은 군집화·MLP 실습은 CPU 또는 RTX 3050 4GB로 진행한다. GPU 메모리가 부족하면 모델을 키우기보다 배치 크기를 줄여 원리를 확인한다.

## 5. CNN과 이미지 XAI 검증

### 강의·자료

Deep Learning Specialization의 **Convolutional Neural Networks**를 수강한다. 이후 KAIST XAI의 CAM 계열 방법을 공부하고, [Captum의 이미지 해석 실습](https://captum.ai/tutorials/TorchVision_Interpret)을 참고한다.

### 실습

사전학습된 이미지 분류 모델에 Grad-CAM을 적용한다. 맞힌 이미지와 틀린 이미지를 함께 고르고, 모델이 중요하게 본 영역을 확인한다.

그다음 중요 영역을 가렸을 때와 같은 크기의 다른 영역을 가렸을 때를 비교한다. 원래 확인하려던 클래스의 점수가 어떻게 변하는지 기록한다.

영역을 가리는 행위 자체가 부자연스러운 입력을 만들 수 있으므로, 검은색 가림과 흐림 처리 등도 비교한다.

### 완료 기준

- CNN의 채널, 특징맵, 출력 크기를 설명할 수 있다.
- 히트맵과 실제 출력 변화가 일치하는지 확인한다.
- 눈에 그럴듯한 그림만으로 설명의 정확성을 판단하지 않는다.
- 설명이 불안정하거나 해석하기 어려운 사례도 함께 기록한다.

**장비:** 작은 입력과 배치 크기를 사용한 사전학습 CNN 분석은 RTX 3050 4GB에서 진행한다. 큰 이미지 모델을 처음부터 학습하는 작업은 이번 목표에서 제외한다.

## 6. 트랜스포머와 근거 분석

### 강의·자료

Deep Learning Specialization의 **Sequence Models**를 공부한다. 순환신경망에서 attention과 Transformer로 이어지는 흐름을 정리한다.

보조 자료로 다음 논문을 읽는다.

- [Lost in the Middle](https://arxiv.org/abs/2307.03172): 긴 문맥에서 근거 위치에 따라 성능이 달라지는 문제
- [Making Retrieval-Augmented Language Models Robust to Irrelevant Context](https://arxiv.org/abs/2310.01558): 관련 없는 문맥에 대한 견고성

### 실습

작은 예제로 Q, K, V와 attention 계산을 따라간다. 이후 Transformer의 주요 선형 계층과 MLP, 그리고 가중치, 활성값, KV 캐시를 구분한다.

RAG에서는 같은 질문에 다음 입력을 제공해 답변을 비교한다.

| 조건 | 확인하려는 것 |
|---|---|
| 실제 파이프라인이 선택한 근거 | 현재 서비스의 전체 결과 |
| 사람이 확인한 필요한 근거 | 필요한 정보가 있을 때의 답변 능력 |
| 필요한 근거와 방해 자료 | 관련 없는 정보에 흔들리는 정도 |
| 필요한 근거를 제거한 입력 | 근거 없이 답을 만들어내는 정도 |

질문과 생성 설정을 고정하고, 정답뿐 아니라 부가 설명, 수치, 조건, 인용도 확인한다.

이 비교에서 결과가 달라졌다고 곧바로 특정 부품 하나만 원인이라고 단정하지 않는다. 근거의 내용뿐 아니라 순서, 길이, 방해 자료도 달라질 수 있기 때문이다.

### 완료 기준

- Transformer에서 큰 가중치 행렬이 어디에 있는지 설명할 수 있다.
- 모델 가중치와 KV 캐시의 메모리를 구분한다.
- 필요한 근거가 제공되어도 틀리는 사례를 구체적으로 설명한다.
- 프롬프트, 입력 형식, 잘림, 모델 능력을 확인한 뒤 추가 학습의 필요성을 판단한다.

**장비:** 작은 attention 구현과 소형 모델 분석은 현재 노트북에서 진행한다. 큰 교사 모델이 필요한 답변 비교는 API나 별도 장비를 사용한다.

## 7. 양자화 원리와 직접 구현

이 단계부터 모델 압축을 본격적으로 다룬다. 기존 양자화 모델을 실행하는 것과 직접 압축 과정을 설계하는 것을 구분한다.

### 강의·자료

다음 순서로 학습한다.

1. [Quantization Fundamentals with Hugging Face](https://www.deeplearning.ai/short-courses/quantization-fundamentals-with-hugging-face/)
2. [Quantization in Depth](https://www.deeplearning.ai/short-courses/quantization-in-depth/)
3. [MIT 6.5940](https://hanlab.mit.edu/courses/2024-fall-65940)의 양자화 강의와 관련 실습

구현 방식을 선택할 때는 [Hugging Face 양자화 문서](https://huggingface.co/docs/transformers/quantization/overview)에서 지원 모델과 실행 환경도 확인한다.

### 실습

작은 텐서를 대상으로 다음을 직접 구현한다.

- 부동소수점 값을 정수 구간에 대응시키기
- scale과 zero-point 계산
- 양자화한 값 복원
- 원본과 복원값의 오차 계산
- per-tensor·per-channel 방식 비교

이후 작은 모델의 선형 계층에 적용한다. 가중치 복원 오차만 보지 않고, **같은 입력을 넣었을 때 계층 출력이 얼마나 달라지는지**도 확인한다.

전체 모델 실험에서는 같은 원본 모델을 사용하고, 양자화 방식과 비트 수를 바꾸어 비교한다. 모델 자체가 달라진 경우는 별도 비교로 분리한다.

함께 정리할 개념은 다음과 같다.

| 개념 | 공부할 질문 |
|---|---|
| PTQ | 학습이 끝난 모델을 어떻게 압축하는가? |
| 보정 데이터 | 어떤 입력으로 압축 오차의 영향을 확인하는가? |
| QAT | 학습 중 양자화의 영향을 어떻게 반영하는가? |
| Weight-only 양자화 | 가중치를 줄여도 어떤 메모리는 그대로 남는가? |
| 실행 커널 | 작은 파일이 왜 항상 빠르게 실행되지는 않는가? |

### 완료 기준

- 간단한 양자화기를 직접 구현한다.
- 비트 수와 복원 오차의 관계를 측정한다.
- 파일 크기, 실제 메모리, 응답 속도를 구분한다.
- 보정 데이터와 최종 평가 데이터를 분리한다.
- 압축 모델이 틀린 답을 내는 사례를 원본 모델과 비교한다.

**장비:** 텐서, 단일 계층, 작은 모델 실습은 RTX 3050 4GB로 진행한다. 전체 모델 보정은 원본 가중치와 중간 계산 때문에 더 많은 메모리가 필요할 수 있으므로, CPU 처리나 큰 GPU 환경을 검토한다.

## 8. 지식 증류와 압축 보정

양자화는 값을 표현하는 방식을 바꾸고, 증류는 교사 모델의 출력을 이용해 학생 모델을 학습한다. 두 방법이 각각 무엇을 바꾸는지 먼저 나누어 이해한다.

### 강의·자료

- [PyTorch 공식 Knowledge Distillation 튜토리얼](https://docs.pytorch.org/tutorials/beginner/knowledge_distillation_tutorial.html)
- MIT 6.5940의 지식 증류 강의

첫 실습은 언어 모델보다 작은 이미지 분류 모델로 진행한다. PyTorch 공식 튜토리얼은 4GB GPU를 실습 환경으로 제시한다.

### 실습

같은 학생 모델에 대해 다음 두 조건을 비교한다.

- 정답 레이블만 사용한 학습
- 정답 레이블과 교사 출력 분포를 함께 사용한 학습

온도와 손실 비중을 바꾸며 결과를 확인한다. 교사는 기울기를 계산하지 않고, 학생에게만 학습이 적용되는지도 점검한다.

이후 작은 언어 모델로 범위를 넓힌다. 이때 다음 두 방법을 구분한다.

| 방법 | 사용하는 정보 |
|---|---|
| 교사 답변을 활용한 SFT | 교사가 생성한 텍스트 |
| 로짓 기반 증류 | 각 토큰에 대한 교사의 출력 분포 |

로짓 기반 증류의 첫 실험은 토크나이저와 어휘가 호환되는 모델을 선택한다. 교사가 생성한 답변도 자동으로 정답으로 간주하지 않고, 근거와 비교해 잘못된 예시는 수정하거나 제외한다.

### 완료 기준

- 교차엔트로피, KL divergence, 온도의 역할을 설명한다.
- 같은 학생 모델에서 증류의 효과를 비교한다.
- 교사보다 학생이 잘하는 사례와 못하는 사례를 모두 살펴본다.
- 증류 후 점수가 올라도 새로운 질문에 일반화되는지 확인한다.

**장비:** 작은 CNN 증류는 RTX 3050 4GB에서 진행한다. 언어 모델의 교사와 학생을 동시에 올리는 실험은 더 큰 GPU를 사용하는 편이 현실적이다. 교사 출력을 미리 저장하면 동시 적재 부담을 줄일 수 있지만, 저장 공간과 출력 형식도 고려한다.

## 9. 코드북 양자화와 E-Means

### 먼저 이해할 점

**E-Means는 언어 모델 전체를 자동으로 압축하는 완성된 도구가 아니다.** k-means 문제를 푸는 군집화 알고리즘이며, 모델 압축에서는 가중치 벡터를 대표할 코드북을 만드는 과정에 활용할 수 있다. 공식 설명과 구현은 [E-Means 프로젝트](https://e-means.github.io/)와 [Faiss 코드](https://github.com/facebookresearch/faiss/tree/main/contrib/e_means)에서 확인한다.

따라서 학습 순서는 다음과 같이 잡는다.

**k-means → 벡터 양자화 → 코드북 저장·복원 → E-Means 적용 → 모델 출력과 답변 평가**

### 실습

처음에는 작은 선형 계층의 가중치를 일정 길이의 벡터로 묶는다. 비슷한 벡터들을 군집화하고, 각 벡터 대신 대표 벡터의 번호를 저장한다.

예를 들어 가중치 네 개를 하나의 벡터로 묶고 대표 벡터를 256개 만든다면, 각 묶음의 번호는 8비트로 표현할 수 있다. 번호만 계산하면 가중치당 2비트지만, 실제 파일에는 코드북과 부가 정보도 들어가므로 전체 크기는 따로 측정해야 한다.

이 구조에서 **코드북 학습 알고리즘만 Lloyd 방식과 E-Means로 바꾸어 비교**한다.

고정할 조건은 다음과 같다.

- 원본 가중치와 데이터
- 벡터 길이와 코드북 크기
- 초기화·난수 조건
- 저장 형식과 전체 용량 계산 방법
- 평가 입력과 측정 방법

비교는 두 관점에서 진행한다.

| 비교 | 확인할 질문 |
|---|---|
| 비슷한 오차에 도달할 때까지의 시간 | 코드북 제작이 얼마나 빨라지는가? |
| 같은 계산 시간에서의 오차 | 정해진 자원 안에서 더 좋은 코드북을 만드는가? |

이후 코드북을 작은 모델에 적용하고, 가중치 오차, 계층 출력 오차, 최종 성능을 순서대로 확인한다.

### 완료 기준

- 코드북과 인덱스를 저장하고 원래 가중치 형태로 복원한다.
- 부가 정보를 포함한 실제 압축 크기를 계산한다.
- 같은 표현 구조에서 군집 방식의 효과를 비교한다.
- E-Means의 군집화 속도와 모델의 추론 속도를 구분한다.
- 복원 오차가 작아도 업무 답변이 나빠지는 사례를 확인한다.

**장비:** 작은 가중치 행렬과 제한된 표본의 군집화는 CPU 또는 RTX 3050 4GB에서 시작한다. 전체 언어 모델의 코드북 학습과 보정은 모델 크기에 따라 큰 RAM이나 GPU가 필요하다.

처음에는 복원한 가중치로 품질을 평가해도 된다. 다만 실행 시 전체 가중치를 다시 부동소수점으로 펼쳤다면, 이를 저메모리 압축 추론이라고 표현하지 않는다. 압축 상태를 활용하는 실행 커널은 별도의 구현 과제다.

## 10. 모델 압축 포트폴리오

### 프로젝트 주제

> **업무용 RAG의 조건 보존과 인용 정확성을 고려한 저비트 언어 모델 압축**

목표는 작은 파일을 만드는 데서 끝나지 않는다. 어떤 압축 방식이 제작 비용을 줄이고, 업무에 필요한 답변 능력을 얼마나 유지하는지 설명한다.

### 실험 단계

| 단계 | 비교 대상 | 확인할 내용 |
|---|---|---|
| A | 원본 정밀도의 모델 | 품질과 자원 사용의 기준 |
| B | 기존 양자화 방식 | 사용할 수 있는 현실적인 기준선 |
| C | Lloyd 기반 코드북 양자화 | 직접 구현한 압축 구조의 효과 |
| D | 같은 구조에 E-Means 적용 | 코드북 학습 방식의 차이 |
| E | D에 증류 보정 추가 | 학습으로 회복되는 품질과 추가 비용 |

핵심은 C와 D의 비교다. 벡터 길이, 코드북 크기, 용량 조건을 유지하고 군집 방식의 영향을 확인한다. E는 별도 실험으로 두어 증류의 효과가 E-Means의 효과와 섞이지 않게 한다.

### 평가 항목

| 영역 | 확인할 내용 |
|---|---|
| 제작 비용 | 압축·보정 시간과 최대 메모리 |
| 압축 결과 | 실제 파일 크기와 부가 정보 |
| 수치적 변화 | 가중치·계층 출력 오차, 언어 모델 지표 |
| 답변 품질 | 핵심 결론과 부가 설명의 정확성 |
| 조건 보존 | 수치, 단위, 부정, 적용 범위 |
| 출처 | 인용 대상의 존재와 주장에 대한 뒷받침 |
| 근거 부족 대응 | 자료가 없을 때 단정하거나 만들어내는지 |
| 실제 실행 | 첫 답변 시간, 전체 시간, 메모리 |

먼저 **같은 근거를 제공하는 비교**로 생성 모델의 차이를 확인한다. 이후 실제 검색을 포함한 RAG 흐름에서도 확인하되, 검색 실패와 모델 답변 실패는 나누어 기록한다.

기존 업무 질문은 회귀 평가로 활용하고, 개발 중 사용하지 않은 질문과 문헌도 최종 평가에 포함한다. 학습·보정에서 제외한 평가 문헌을 RAG 검색 대상에서도 제거할 필요는 없다. 평가 질문에 답하는 데 필요한 자료는 실제 사용 상황처럼 검색할 수 있어야 한다.

### 최종 결과물

- 압축과 평가를 다시 실행할 수 있는 코드·명령
- 원본 모델과 데이터의 출처·버전
- 학습, 보정, 평가 데이터 분리 기준
- 고정한 조건과 변경한 조건
- 품질, 용량, 속도, 메모리 비교
- 실패 사례와 적용 범위
- 저장 형식과 실행 방식의 제한
- 모델, 코드, 데이터의 사용 조건

성능이 모든 항목에서 좋아져야 프로젝트가 성립하는 것은 아니다. 코드북 제작은 빨라졌지만 답변 품질은 비슷할 수 있고, 파일은 작아졌지만 추론은 느려질 수도 있다. 이런 차이를 재현 가능한 실험으로 설명하는 것도 중요한 결과다.

## 11. 4GB GPU 실습 범위

장비를 바꾸기 전에 현재 노트북에서 할 수 있는 실습을 충분히 진행한다.

| 작업 | RTX 3050 4GB 기준 |
|---|---|
| 회귀, 트리, 표 데이터 XAI | CPU로 충분 |
| k-means·작은 E-Means 실험 | CPU 또는 GPU로 가능 |
| 작은 MLP·CNN 학습 | 배치와 모델 크기를 조절해 진행 |
| 사전학습 CNN의 Grad-CAM | 작은 입력·배치로 진행 |
| 공식 CNN 증류 실습 | 우선 실습 대상으로 적합 |
| 양자화기·코드북 직접 구현 | 작은 텐서와 계층부터 진행 |
| 소형 언어 모델의 제한된 추론 | 모델, 문맥 길이, 실행 방식에 따라 확인 |
| 언어 모델 일부 계층의 압축 | 표본과 중간 계산을 제한해 진행 |
| 전체 언어 모델 보정·증류 | 더 큰 GPU 또는 CPU 오프로딩 검토 |
| 큰 교사·학생 동시 실행 | 별도 GPU 환경 사용 |
| 큰 모델의 QAT·전체 파인튜닝 | 별도 고메모리 환경에서 진행 |

**압축 모델이 4GB GPU에서 실행된다는 사실은 그 모델을 4GB에서 압축하거나 학습할 수 있다는 뜻이 아니다.** 제작 과정에는 원본 가중치, 활성값, 기울기, 옵티마이저 상태 등이 추가로 필요할 수 있다.

큰 GPU는 전체 모델 실험이 필요해지는 시점에 선택한다. 모델 크기만으로 용량을 정하지 않고, 실제로 사용할 학습 방식, 문맥 길이, 배치, 중간 버퍼를 기준으로 작은 실행부터 측정한다.

## 12. SFT와 DPO의 배치

기존에 접한 방법들도 역할을 나누어 정리한다.

| 방법 | 주요 역할 | 이번 계획에서의 위치 |
|---|---|---|
| SFT | 예시를 통해 원하는 출력 행동 학습 | 필요할 때 보정 실험 |
| LoRA | 일부 추가 파라미터를 통한 효율적인 가중치 갱신 | 학습 구현 방법으로 활용 |
| DPO | 선호하는 답변과 비선호 답변의 차이 학습 | 선호 데이터가 준비된 이후 |
| 증류 | 교사의 답변, 분포, 표현을 학생 학습에 활용 | 핵심 학습 과정 |
| 양자화 | 가중치 등의 표현 정밀도와 저장 비용 축소 | 핵심 학습 과정 |
| E-Means | 군집화 최적화와 코드북 학습에 활용 | 최종 압축 프로젝트 |

SFT, DPO, LoRA를 반드시 순서대로 적용하지는 않는다. **무엇을 바꾸려는지와 어떤 데이터가 있는지를 먼저 판단한다.**

검색된 근거를 활용하는 학습이 필요하다면 [RAFT](https://arxiv.org/abs/2403.10131)를 후속으로 검토한다. 도메인 추가 사전학습이나 특정 모델 전용 튜닝은 이번 기본 과정에서 제외하고, 평가 결과로 필요성이 확인되면 별도 계획을 세운다.

## 13. 학습 내용 기록 방식

각 단계의 기록은 강의 요약과 실험 기록을 구분한다. 실험 글에는 다음 내용을 남긴다.

1. 해결하려는 질문과 예상한 결과
2. 사용한 데이터, 모델, 실행 환경
3. 고정한 조건과 바꾼 조건
4. 실제 결과와 실패 사례
5. 결과로 설명할 수 있는 범위
6. 다음에 확인할 내용

각 글의 마지막에는 **알게 된 점, 아직 모르는 점, 다음 실험**을 짧게 적는다.

최종적으로는 RAG 서비스를 다루는 경험을 바탕으로 모델의 행동을 분석하고, 압축 방식을 직접 구현하고, 제한된 장비에서 어느 정도의 품질을 유지할 수 있는지 설명하는 포트폴리오를 만든다.
